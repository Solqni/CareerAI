1. 引言
1.1 编写目的
本需求规格说明书为"AI求职与职业成长智能体"（以下简称CareerAI）课程设计项目提供完整的需求描述。本项目属于《软件项目开发实战》课程——AI智能体应用开发方向，选题对应课程任务书推荐方向"AI求职与职业成长智能体"，旨在构建一个集简历解析、岗位分析、能力匹配、学习规划、面试准备和职业成长追踪于一体的AI智能体平台。系统定位于解决大学生求职者在求职与职业成长过程中面临的核心问题：
信息不对称：求职者不了解目标岗位的技能要求，对行业需求缺乏认知；
简历准备困难：不知道如何针对岗位优化简历，缺乏个性化指导；
面试准备不足：缺乏针对性的面试题目和模拟练习机会。
本项目采用课程任务书规定的技术路线B（Python + FastAPI + LangChain），通过真实接入大语言模型（LLM），实现RAG知识库、Tool Calling、Agent工作流等核心AI能力，满足课程设计各项验收指标。
1.2 项目定位
本项目定位为课程设计级别的AI智能体应用系统，强调核心功能的完整实现和AI能力的合理运用。系统采用B/S架构，后端使用FastAPI + LangChain，前端使用Vue 3，数据库使用PostgreSQL + pgvector，缓存使用Redis，LLM通过API调用（如DeepSeek），整体通过Docker Compose一键部署。

3.3.2 匹配度计算方式
匹配度 = 技能匹配分（50%）+ 经验匹配分（30%）+ 学历匹配分（20%）。技能匹配：逐项对比用户技能与岗位要求技能，计算匹配率。经验匹配：对比用户项目经历与岗位要求年限和领域的相关性。最终由LLM基于以上数据给出综合评分和文字分析。
3.4 简历优化模块（M4）
Agent根据目标岗位要求，对用户简历内容进行分析并生成优化建议：
关键词优化：识别简历中缺少的目标岗位关键词，建议补充；
经历量化建议：建议将描述性经历改为量化成果表达；
内容增强建议：针对能力短板，建议补充相关项目经验或证书描述。
重要原则：Agent不得编造用户未提供的经历或技能，所有优化建议必须基于用户真实信息。实现方式：调用LLM，传入简历内容和岗位要求，使用Pydantic定义返回结构，让LLM返回结构化优化建议列表。
3.5 面试准备模块（M5）
Agent基于目标岗位和用户简历，提供面试准备服务：
面试题生成：根据岗位要求，调用LLM生成针对性面试题（技术题、项目题、行为题）；
模拟面试：Agent扮演面试官角色，与用户进行多轮文本对话面试；
答案评估：对用户回答进行多维度评估（逻辑性、完整性、专业性）；
反馈报告：每轮面试后生成评估报告（优点、不足、改进建议）。

5. RAG知识库需求

系统必须实现完整的RAG流程，满足课程任务书要求：
原始文档 → 文档解析（支持PDF/Word/Markdown/TXT） → Chunk切分（Chunk Size可配置，合理设置Overlap） → Embedding（调用DeepSeek Embedding API） → 向量存储（pgvector） → 用户问题 → Query Embedding → 相似度检索（TopK可配置） → 构建上下文 → LLM生成回答

5.3 RAG配置参数
Chunk Size：建议500-1000字符，根据文档类型调整；
Chunk Overlap：建议50-100字符，保证上下文连贯；
TopK：默认返回5个最相似Chunk；
相似度阈值：可配置最低相似度，过滤不相关结果。
6. Agent与Tool Calling需求
6.1 Agent工作流
Agent必须实现真实的执行流程，不能是简单的"Prompt→LLM→Answer"模式：
用户任务 → Agent理解任务 → 选择Tool → 执行Tool → 获得Observation → 判断任务是否完成 → 必要时继续调用Tool → 最终结果
使用LangGraph编排Agent工作流，支持多步骤任务的状态管理和流程控制。Agent需能根据任务执行结果判断是否需要继续调用工具，并具备异常处理能力。

6.3 Agent异常处理
Tool调用失败时，Agent应能重试或降级处理；
LLM接口异常时，返回友好提示而非系统崩溃；
Agent无法完成任务时，应明确告知用户原因和建议。
7. Memory需求
7.1 短期记忆（必须）
支持基本多轮会话上下文：使用LangChain的ConversationBufferMemory，存储当前会话的对话历史；
通过conversation和message表持久化对话记录，支持查看历史对话；
Agent在每次对话中能引用之前的上下文信息。
7.2 长期记忆（加分项）
用户能力画像持久化：用户技能、经历、学习进度等数据长期保存；
学习历史记录：用户过往的学习计划和完成情况；
岗位偏好：用户浏览和匹配过的岗位记录。
8. 外部接口需求
8.1 用户界面
前端采用Vue 3 + TypeScript，界面要求：
仪表盘视图：首页展示能力画像概览、匹配度趋势、学习进度等关键指标；
对话式交互：核心Agent交互采用聊天界面，支持多轮对话和流式输出；
报告可视化：匹配报告使用雷达图、柱状图等图表展示；
文件上传：支持简历PDF/Word上传、JD文本粘贴；
响应式设计：适配PC端访问。
8.2 软件接口
LLM Chat API：DeepSeek Chat API，用于简历解析、JD分析、匹配分析、面试题生成等；
LLM Embedding API：DeepSeek Embedding API，用于文本向量化；
REST API：FastAPI提供RESTful接口，前端通过Axios调用；
SSE流式输出：Agent分析过程和结果支持Server-Sent Events流式输出。
8.3 结构化输出
LLM返回的结构化数据使用Pydantic模型进行校验和解析（课程任务书建议项）；
简历解析结果、JD解析结果、匹配报告、学习计划等均使用Pydantic定义数据模型。
9. 非功能性需求
9.1 性能
Agent分析任务应在15秒内返回结果（含流式输出）；
支持课程演示场景下的并发访问；
合理设计Prompt和Token使用策略，控制调用成本。
9.2 安全性
LLM API Key通过环境变量配置，不得提交至代码仓库（任务书必须项）；
用户密码使用bcrypt哈希存储；
JWT Token认证，会话隔离；
用户简历等敏感数据加密存储。
9.3 可维护性
日志记录：Agent调用链路、Tool调用、Token消耗等关键操作记录日志；
模块化设计：后端按功能模块分层（router → service → repository），Agent、RAG、Tool等组件松耦合；
配置管理：数据库连接、LLM API Key等通过环境变量或配置文件统一管理。
10. Git代码管理要求
根据课程任务书要求，项目必须使用Git进行版本管理：
持续commit，保留清晰开发记录（不允许只在最后一次性提交）；
建议上传到Gitee，所有成员加入仓库；
每名成员应有实际Commit记录，用于判断个人贡献；
建议使用Feature Branch分支管理（feature/user、feature/rag、feature/agent等）；
Commit规范：feat/fix/refactor/docs/test等前缀标注。
11. Docker Compose部署要求
根据课程任务书要求，项目必须使用Docker Compose统一部署：
docker-compose.yml包含服务：frontend（Vue 3）、backend（FastAPI）、postgres（PostgreSQL + pgvector）、redis（Redis）、agent-service（Agent服务）；
必须提供：Dockerfile、docker-compose.yml、环境变量模板(.env.example)、初始化SQL、部署说明；
推荐做到 docker compose up -d 一键启动所有服务；
建议部署到云服务器，实现公网访问。
12. 软件测试要求
根据课程任务书要求，必须完成以下测试：
12.1 业务功能测试
用户注册登录、权限验证、简历上传解析、JD解析、匹配分析、学习计划管理、面试模拟等核心业务流程。
12.2 RAG测试
知识库中有答案的提问、无答案的提问、模糊问题、多文档问题、容易产生幻觉的问题。
12.3 Agent测试
单Tool任务、多Tool任务、Tool调用失败、参数错误、找不到数据、Agent无法完成任务、LLM接口异常。
